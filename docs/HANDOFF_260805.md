## 5. 이 저장소에서 반드시 지킬 것

1. **SQL 은 파일로 만들지 말고 채팅에 코드블록으로 전문을 줄 것.**
   Windows 에서 `.sql` 은 연결된 앱이 없어 **더블클릭해도 안 열린다.** 2026-08-05 에
   지적받았다. DDL/RLS 는 대표님이 Supabase SQL Editor 에 붙여넣어 실행한다.
2. **문서는 3개뿐이다** — 규칙 `CLAUDE.md` / 현재상태 `docs/PROGRESS.md` /
   과거경위 `docs/WORK_LOG.md`. **새 문서 파일을 만들지 말 것**(이 인계 파일은 예외적
   일회성 스냅샷이다). 의미 있는 작업을 끝낼 때마다 **요청 없이도** `PROGRESS.md` 갱신.
3. **버전 락스텝** — `app.js` 의 `_APP_V` · `sw.js` 의 `CACHE` · `바로알바.html` 의
   `?v=` 4곳(app.js/shared-lang.js/style.css/app_ui.js)을 **같은 번호로** 올려야 한다.
   하나라도 빠지면 옛 파일이 캐시에서 그대로 나간다. 현재 **617**.
4. **버그를 고칠 때는 새로 설계하지 말고, 같은 문제를 이미 푼 화면을 찾아 그대로 가져올 것.**
   이 저장소는 **사본 버그**가 반복적으로 나온다 — 하나 고쳤으면 **같은 코드가 더 있는지
   반드시 grep** 할 것(추천 보상 3곳, 프로모션 상수 2곳, 알림 쿼리 2곳 전부 이 부류였다).
5. **"코드를 읽어서 맞다"로 끝내지 말 것.** 이 저장소의 실패는 대부분 **조용한 실패**다 —
   DB 스키마 드리프트는 400 을 삼키고, CSS 는 문법이 틀리면 그 선언만 조용히 버리고,
   권한은 UI 만 막혀 있고 DB 는 열려 있었다. **라이브 REST · 헤드리스 크롬 계산값 ·
   실제 거부 응답**으로 확인할 것.
6. **감사 도구는 "통과"가 아니라 "심어둔 버그를 잡는지"로 검증할 것.** 0건은 깨끗하다는
   뜻일 수도, 아무것도 안 보고 있다는 뜻일 수도 있다(실제로 밟았다).
