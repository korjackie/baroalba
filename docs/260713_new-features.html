Critical Infra
📦 PWA 캐시 드리프트 — 3중 근본원인 발견/해결
"고쳤다고 했는데 왜 반영이 안 되냐"가 반복된 진짜 이유. 겹겹이 쌓인 3개의 독립적인 버전관리 구멍을 전부 찾아냈습니다.
CRITICAL #1
index.html — v1.4.1 시절 그대로 고정된 유령 파일
프로젝트 루트의 index.html이 4,200줄짜리 구버전(v381) 전체 사본으로 남아있었고, 자체 버전가드가 한 번만 리다이렉트하고 이후엔 계속 이 구버전을 서빙하고 있었음. 무조건 최신 바로알바.html로 리다이렉트하는 10줄짜리 스텁으로 전면 교체.
CRITICAL #2
head 스크립트 버전 상수가 app.js와 따로 놀고 있었음
바로알바.html head의 자체 버전값(V='421')이 app.js의 _APP_V와 별도로 하드코딩돼 있어서, _APP_V를 아무리 올려도 두 값이 영원히 안 맞아 캐시 초기화 로직 자체가 세션 내내 한 번도 실행되지 않았음. head 버전체크를 통째로 삭제하고 localStorage._baroV 하나로 판단하도록 단일화.
CRITICAL #3
app.js/style.css/shared-lang.js 태그에 버전 쿼리 자체가 없었음
위 두 가지를 고쳐도 여전히 반영이 안 됐던 진짜 마지막 원인 — 스크립트/CSS 태그에 ?v=가 아예 없어서 Service Worker의 캐시우선 전략이 이 파일들을 영구적으로 캐시할 수 있었음. 세 태그 모두 ?v=444 부여, 이후 배포마다 5곳(app.js _APP_V·SW등록쿼리, sw.js CACHE, HTML 3태그)을 동시에 올리는 것으로 프로세스 확정.
Baromeeting

7/9 최초 개설관리 기능 추가부터 시작해, 신청→승인→채팅→추적까지 전 과정을 실제로 돌려보며 발견된 버그를 하나씩 완성했습니다.
CRITICAL FIX
익명 닉네임/아바타 저장이 처음부터 전부 실패하고 있었음
참가자가 닉네임을 설정해도 실제로는 저장이 안 돼서 채팅방 입장 자체가 막히는 근본 버그 발견. 저장 로직 수정 + 오픈카톡 스타일 캐릭터 아바타(12종 이모지) 선택 기능 신규 추가.
FEAT
관리자 승인 단계 + 정원 카운트 실제값 재계산
신청 즉시 확정되던 방식에서 관리자 승인 단계 추가. 여성/남성 정원 카운트가 승인 내역과 어긋나던 문제를, 매번 실제 gathering_applications 승인건수로 재계산하는 방식(멱등적)으로 근본 수정.
FEAT
실시간 추적화면 + 지도 좌표 확보 + 공유하기
신청 완료 후 카운트다운·단계·지도가 있는 추적화면(바로알바/바로모임과 동일 패턴) 연결. 바로미팅에 lat/lng 저장 추가로 지도 마커 표시 가능해짐. 유일하게 없었던 카카오톡 공유 기능도 추가.
FEAT

UX
단체채팅 헤더 재설계 — 참가자수/나가기/내프로필 분리
"나는 OO으로 표시돼요" 문구가 참가자수 표시 영역을 통째로 가려서 참가자 목록 기능이 안 보이던 문제 해결. 👥 N명은 항상 노출, "나가기"는 옆에 작은 링크로, 내 캐릭터+닉네임은 헤더 우측 배지로 분리.

뒤로가기를 눌렀을 뿐인데 참가취소로 처리되던 문제
채팅 닫기(뒤로가기/제스처)와 명시적 "나가기" 버튼이 뒤섞여 있었음. 뒤로가기는 항상 단순 닫기로, 참가취소 확인창은 오직 "나가기" 버튼을 눌렀을 때만 뜨도록 분리.

FEAT

FEAT
지역 빠른이동 — 출장 중에도 원터치로 지도 이동

FEAT

기존 스포츠/취미/친목/기타 4종에 챌린지 추가. 지도 카테고리 필터도 신규 지원.
