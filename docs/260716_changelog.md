### 발견된 근본 원인 패턴 (반복적으로 나타난 것)

이번 구간에서 가장 자주 반복된 패턴은 **"화면이 4개 파일(`바로알바.html`/`app.js`/
`app_ui.js`/`style.css`)에 나뉘어 있는데, 그중 일부만 보고 결론 내린 것"**이었다.

- 관리자페이지(`admin.html`) 키보드 가림을 `visualViewport`로 세 번이나 새로 짜려다,
  진짜 원인은 `window._onNativeKbChange`가 정의조차 안 돼있었던 것으로 판명 (13-7 원칙
  확립의 계기).
- 오늘(07.16) 전수감사에서도 "당일정산 송금/전자계약서가 죽은 코드"라고 처음
  잘못 결론 냈다가, `app_ui.js`를 뒤늦게 확인하고 이미 완전히 구현돼 있었음을 발견 —
  `app.js`만 grep해서 생긴 오판.
- 상태표시줄 가림은 세 차례의 CSS/JS 미세조정 시도 끝에, 같은 세션에서 이미 읽었던
  `.full-panel`의 정답 패턴(`top:var(--sat-safe)`)을 `.mpsub-panel`에 적용하지 않고
  있었다는, 정작 스스로 만든 코드의 내부 불일치가 원인으로 드러남.
- 관리자 바로스팟 신청목록이 아예 안 뜨던 버그의 진짜 원인은 존재하지 않는 컬럼
  (`created_at`, 실제로는 `applied_at`)을 조회하고 있었던 것.

### 신규 도입된 예방 장치

- **`.mpsub-panel.show` 등 클래스 기반 범용 감시**: 새 서브패널이 추가돼도 개별 등록
  없이 백버튼/키보드 처리가 자동 커버되도록 popstate 캐스케이드·`WATCH_IDS`·
  `_onNativeKbChange`를 클래스 셀렉터 기반으로 전환.
- **디자인 토큰 96곳 통일**: `--red`/`--purple`/`--blue`/`--green` — 같은 색을 매번
  하드코딩하던 관행을 CSS 변수 참조로 정리(값 자체는 불변, 안전한 리팩터링).
- **`app_ui.js` 버전 lockstep 편입**: 캐시버스팅 쿼리가 아예 없던 것을 발견, 5곳 동시
  버전 동기화 체계에 추가.
