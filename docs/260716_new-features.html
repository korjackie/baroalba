Critical · Root Cause
📍 상태표시줄 가림 — 4번째 시도 만에 진짜 원인 특정
세 차례의 CSS/JS 미세조정으로도 해결 안 됐던 문제. 결국 원인은 같은 프로젝트 안의 두 화면 유형이 서로 다른 방식을 쓰고 있었다는 것.
ROOT CAUSE
.mpsub-panel이 .full-panel과 다른 방식으로 상태표시줄 아래를 침범
마이페이지 등 메인 탭 화면(.full-panel)은 top:var(--sat-safe)로 패널 자체가 상태표시줄 아래서 시작하는데, 프로필편집 등 서브화면(.mpsub-panel)만 inset:0으로 화면 맨 위부터 꽉 채우고 헤더 padding으로만 보정하고 있었음. 패널 위치 자체를 통일하고, --sat 실측값을 인라인 style로 재차 강제 적용.
BUG
프로필편집 자기소개 입력 시 키보드 가림 (2단계 수정)
1차: 키보드가 "새로 열릴 때"만 포커스 요소를 스크롤하도록 수정. 2차(사용자 재확인 요청으로 재검토): 키보드가 이미 열린 채로 다른 입력창으로 포커스만 옮기는 경우(예: 생년월일→자기소개)엔 재호출이 안 돼 여전히 가려질 수 있었던 것을 focusin 리스너로 보강.
Full Audit
🔍 전수감사 — 같은 패턴의 버그 12+3건 일괄 발견/수정
"이거 여러 번 반복하지 않도록" 요청에 따라 상태표시줄 수정 직후 전체 코드베이스를 같은 관점으로 재검사.
CRITICAL
업주 "신고하기"/업체사진 업로드가 완전히 죽어있었음
openOwnerReport()/openBizCropModal()이 참조하는 DOM(owner-report-modal, biz-crop-modal)이 실제 배포 파일엔 없고 미배포 목업 폴더에만 존재. 알바생용 화면과 동일 구조로 복원.
BUG
모달 12개 — 하드웨어 뒤로가기 시 앱이 그대로 종료
지원메시지/업주평점/신고/커뮤니티글/사진크롭/게스트로그인/급여계산기/QR/온보딩/레슨등록 모달이 백버튼 등록 체계 어디에도 없었음(.mpsub-panel과 동일 버그 클래스). 전부 등록.
RESTORED
죽어있던 기능 2건 복원 + 오판 1건 정정
banned-agree-overlay(바로심부름 지원 전 금지행위 동의)를 심부름 공고 지원 흐름에 연결, photo-tip-overlay(사진등록 팁)를 프로필사진 빈 슬롯 클릭에 연결. 반면 "당일정산 송금/전자계약서도 죽었다"는 최초 판단은 오판이었음 — app_ui.js를 뒤늦게 확인해 이미 완전히 동작 중임을 확인, 계약서 임금표시 버그(존재하지 않는 컬럼 참조)만 수정.
INFRA
app_ui.js가 버전 캐시버스팅 체계에서 통째로 빠져있었음
캐시버스팅 쿼리 자체가 없어 PWA 캐시에 구버전이 고착될 수 있는 잠재 버그. ?v= 부여 후 5곳 동시 동기화 lockstep에 편입.
DESIGN
색상 하드코딩 96곳을 CSS 변수로 통일
#C8102E(42곳)/#7C3AED/#3B82F6/#16a34a — 값은 그대로 두고 참조만 var(--red) 등으로 통일한 안전한 리팩터링. 회색 계열은 실제로 서로 다른 값이라 이번엔 손대지 않음.
NEW
GA4 분석 이벤트 트래킹 뼈대 신규 추가
_track() 헬퍼 + profile_complete/job_apply/hire_accepted 3개 이벤트 연결. 측정 ID는 아직 플레이스홀더, 발급 즉시 추가 배포 없이 수집 시작 가능.

프로필 편집 + 바로만남 프로필을 한 화면 2탭으로 통합
별개 화면이던 것을 "⚡ 바로알바 프로필" / "💕 바로만남·모임 프로필" 탭으로 통합. ON/OFF 토글 방식도 검토했으나 "탭이 더 직관적"이라는 판단으로 전환. 스킬·경력/자격증·서류도 이 화면으로 이동.
FEAT
사진관리 5칸 통합 시스템 (대표사진 + 포트폴리오 4칸)
대표사진과 포트폴리오가 별개 슬롯이라 헷갈리던 것을 5칸(1번=대표, 나머지=포트폴리오/드래그로 승격 가능) 시스템으로 재구축. 사진 재배치 로직도 검증 안 된 storage.move() 대신 upload+remove 조합으로 교체.

BUG

마이페이지 서브패널(.mpsub-panel) 전부가 뒤로가기 체계에 등록이 안 돼있어 두 번 누르면 앱이 종료되던 문제. 화면 하나씩 고치는 대신 클래스 기반 범용 감시로 한 번에 해결.
Barospot Redesign
💘 바로스팟 — 정원제에서 1:1 매칭 모델로 전면 재설계
07.14 하루 동안 15개 커밋으로 이어진 구조 전환. 이후 실사용 중 발견된 버그들을 며칠에 걸쳐 안정화.
RESTRUCTURE
정원 채우는 그룹 매칭 → 개별 신청·선택 방식으로 전환
남성이 여성 카드에 개별 신청하면 여성이 블라인드 후보 중 선택, 상호수락 시 1:1 채팅이 열리는 구조로 재설계. 평점/노쇼 기준 미달 시 신청 차단, 반경 5km 알림, 선착순 선점 기능도 함께 신설.
CRITICAL
관리자 신청목록이 아예 안 뜨던 버그
존재하지 않는 컬럼(created_at, 실제로는 applied_at)을 조회하고 있었던 것이 원인. 지도 마커 미표시, 확대 시 안정성 문제도 함께 수정.
FEAT
사후 호감표시 → 상호수락 → 1:1 채팅 (통합 채팅 스키마 신설)
만남 이후에도 서로 호감을 표시하고 상호수락 시 별도 1:1 채팅이 열리는 후속 매칭 플로우 신규 구축.
FEAT
실시간 위치공유(거리 트래커) 핵심 엔진
바로미팅 참가자 간 실시간 위치공유 + 서버사이드 지오코딩 폴백 신규 구축. "도착했어요" 버튼 의미없는 토글 문제도 도착확인 다이얼로그로 개선.
UX
직업군/체형/관심사 프로필 신설 + 카카오톡 공유 딥링크
성별에 맞게 세분화된 직업군·체형 옵션, 관심사 태그. 공유하기가 링크 복사만 되던 것을 카카오톡 실제 공유로 개선.
