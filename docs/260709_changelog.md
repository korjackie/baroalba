### 발견된 근본 원인 패턴 (반복적으로 나타난 것)

이번 세션에서 가장 많이 반복된 버그 패턴은 **"존재하지 않는 함수를 호출하고 있었다"**
는 것이었다.

- `openBottomSheet()` / `closeBottomSheet()` — 바로스팟 "이용권 구매" 버튼이 호출하고
  있었으나 코드 어디에도 정의된 적이 없었음. 원본부터 있던 버그.
- `showCustomConfirm()` — 바로스팟/바로미팅 신청 확인창이 호출했으나 미정의.
  이미 존재하던 `showConfirmDialog()`로 교체.
- `cancelLang()` / `saveLang()` / `selectLang()` — 실제로는 `shared-lang.js`에 정상
  구현되어 있었음(v371에 이미 고쳐짐). 이 셋은 버그가 아니라, 업주 계정 쪽에 이
  화면 자체의 HTML이 없었던 것이 진짜 원인.

즉 "버튼이 눌러도 반응이 없다"는 증상은 매번 원인이 달랐다 — ①함수 자체가 없거나,
②함수는 있지만 실제 DB 반영 로직이 없거나(바로미팅 신청이 토스트만 뜨고 아무것도
저장 안 하던 것), ③애초에 화면(HTML)이 없거나. 셋 다 "캐시 문제"로 오인하기 쉬운
증상이라 주의가 필요하다.

### PWA 캐시 버전에 대한 별도 발견

`바로알바.html`의 `V`, `app.js`의 `_APP_V` / SW 등록 쿼리, `sw.js`의 `CACHE` 키 —
이 세 곳이 동일한 버전 번호로 동기화되어야 클라이언트가 서비스워커 캐시를 강제로
비우고 새 코드를 받는다. 10건 넘는 커밋이 있었음에도 이 번호(381)가 전혀 갱신되지
않고 있었던 것을 발견 — 즉 이번 세션 이전의 여러 수정사항이 실제 사용자 기기에는
전달되지 않고 있었을 가능성이 있다. 381→384로 올리며 이후로는 기능 변경이 있을
때마다 세 곳을 함께 올리는 것으로 프로세스를 바꿈.

## 2. 시스템 구조 변경

### 2-1. 프론트엔드 모듈화 (가장 큰 구조 변경)

```
이전:  바로알바.html  (1.38MB, 인라인 <style>+<script> 전부 포함)

이후:  바로알바.html          349KB   마크업 + API/Config 연동
       assets/css/style.css   72KB   전역 스타일
       assets/js/app.js       912KB  DB 호출 + 핵심 렌더링
       assets/js/app_ui.js    52KB   모달·동의서 등 부가 UI
```

- `backup/` 폴더에 리팩토링 이전 원본 100% 보존 (git 추적 대상에서는 제외)
- 앞으로 이 4파일 체계를 유지하며 작업 — 다시 하나로 합치지 않음
- app.js가 여전히 912KB 단일 파일이라, 공고/모임/결제/채팅 단위로 추가 분리하는
  안이 백로그에 있음 (착수 전, 우선순위 낮음)

### 2-2. 관리자페이지(admin.html) 재구성

```
이전:  대시보드 | 신고관리 | 공고관리 | 회원관리 | 모임관리   (상단 스크롤 탭)

이후:  대시보드 | 바로알바 | 바로모임 | 바로만남 | 설정        (하단 네비게이션)
         ├─ 바로알바: 공고관리 · 회원관리 · 신고처리
         ├─ 바로모임: 모임관리 · 참여회원 · 신고처리
         ├─ 바로만남: 제휴매장 CRUD · 매니저관리 · 쿠폰관리
         └─ 설정: 카테고리 마스터 · 이용권가격 · 관리자계정 · 탈퇴자정리
```

- 뒤로가기는 헤더 '‹' 버튼 하나로 통합 (서브페이지→그룹메뉴→대시보드 순으로 복귀,
  popstate 핸들러와 로직 공유)
- 대시보드는 서비스별 "제목 좌측 + 현황 우측" 1줄 카드로 압축
