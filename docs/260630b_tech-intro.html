1. 버그 분석 — 왜 캐시가 아니었나
🔍 applyLang() 번역 덮어쓰기 메커니즘 shared-lang.js
근본 원인 / 756번 줄

바로알바 앱은 6~7개 언어 번역을 shared-lang.js에서 관리합니다. 페이지 로드 시 applyLang()이 실행되어 .nav-label 요소들의 textContent를 번역값으로 덮어씁니다.

// shared-lang.js 755-756번 줄 (버그) const navKeys = ['nav_map','nav_swipe','nav_applications','nav_chats','nav_profile']; navLabels.forEach((el, i) => { if (navKeys[i]) el.textContent = t(navKeys[i]); }); // TRANSLATIONS.ko (71번 줄) nav_map: '지도', nav_swipe: '스와이프' ← 이 값이 적용됨 // 결과: HTML이 아무리 바뀌어도 JS가 덮어씀 // nav[0] "홈" → '지도' 출력 (nav_map 값) // nav[1] "지도" → '스와이프' 출력 (nav_swipe 값)

왜 다른 수정은 다 됐는가? 다른 텍스트들은 applyLang() 대상이 아님. nav 라벨만 navKeys 배열로 인덱스 기반 적용.

// 수정 — nav_home 신규 추가, navKeys 재정렬 const navKeys = ['nav_home','nav_map','nav_applications','nav_chats','nav_profile']; // 7개 언어 TRANSLATIONS에 nav_home 추가: ko: nav_home:'홈' en: nav_home:'Home' zh: nav_home:'首页' ja: nav_home:'ホーム' vi: nav_home:'Trang chủ' mn: nav_home:'Нүүр' ru: nav_home:'Главная'
🗂️ SW 캐시 전략 — 3개 레이어
캐시 vs 코드 버그 구분이 중요한 이유
레이어대상전략우회 방법
WebView HTTP 캐시모든 리소스브라우저 기본clearCache(true)
SW CacheStorageJS, CSS, 이미지Cache-Firstcaches.delete()
SW HTML 처리.html 파일Network-First (no-store)자동 최신 버전

핵심: HTML은 항상 최신, JS(shared-lang.js)는 Cache-First. 따라서 SW 캐시 버전을 올리지 않으면 구 버전 JS가 계속 사용됨. v300에서 baroalba-v300으로 bump하여 강제 갱신.

3. SW 등록 버전 관리
📦 버전 동기화 규칙
바로알바.html ↔ sw.js 항상 동일 버전
// 바로알바.html const _APP_V = '301'; ← 앱 버전 navigator.serviceWorker.register('./sw.js?v=301'); ← SW 등록 쿼리 // sw.js const CACHE = 'baroalba-v301'; ← 캐시 키 (이전 캐시 자동 삭제)

activate 이벤트에서 k !== CACHE인 모든 캐시 삭제 → SW 버전 올리면 구 JS 캐시 자동 제거.
