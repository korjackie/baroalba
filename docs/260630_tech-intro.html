Realtime
Supabase Realtime 채널 구조

Supabase Realtime WebSocket으로 채팅·모임채팅·위치공유를 실시간 구독. 채널 네이밍 규칙과 구독 테이블을 정리.

채널 패턴 구독 테이블 이벤트 용도 비고
app_chat:{appId} messages INSERT 1:1 채팅 (구직자 ↔ 업주) 기존
location:{appId} worker_locations INSERT / UPDATE 실시간 위치공유 (지도 오버레이) 기존
moim-chat-{gatheringId} gathering_chats INSERT 바로모임 그룹 채팅 신규 2026-06-30
Realtime 구독 패턴 (공통)
// 채널 생성 + 구독 const channel = supabase .channel('moim-chat-' + gatheringId) .on('postgres_changes', { event: 'INSERT', schema: 'public', table: 'gathering_chats', filter: `gathering_id=eq.${gatheringId}` }, payload => handleNewMessage(payload.new)) .subscribe(); // 컴포넌트 언마운트 시 구독 해제 supabase.removeChannel(channel);
Service Worker
Service Worker v284 — 캐시 전략

sw.js v284는 리소스 유형별로 다른 캐시 전략을 적용해 오프라인 지원과 최신 코드 보장을 동시에 달성.

Cache-First (자산)

JS 라이브러리, 이미지, 폰트 등 변경 빈도가 낮은 정적 자산. 캐시 히트 시 즉시 반환, 캐시 미스 시 네트워크 후 캐시 저장.

카카오맵 SDK Supabase JS Cropper.js 토스페이먼츠 SDK

Network-First (HTML/API)

바로알바.html과 Supabase API 요청은 항상 네트워크 우선. 네트워크 실패 시에만 캐시 폴백으로 오프라인 표시.

바로알바.html login.html api/send-push.js supabase REST 요청

Stale-While-Revalidate

캐시된 응답을 즉시 반환하면서 백그라운드에서 최신 버전을 가져와 다음 요청에 반영. 체감 속도와 최신성을 동시에.

공고 목록 이미지 프로필 사진 (avatars) biz-photos

버전 관리

sw.js 버전(v284)은 바로알바.html의 SW_VERSION 상수와 항상 동기화. 버전 불일치 시 강제 업데이트 트리거.

const CACHE_NAME = 'baroalba-v284'; // HTML 내 SW_VERSION과 동기화 필수 self.addEventListener('activate', e => e.waitUntil(clearOldCaches()));
바로모임 · NEW 2026.06.30
바로모임 아키텍처

모임 생성·초대·그룹채팅을 지원하는 신규 기능. gatherings 테이블 + Realtime 채팅 + 플랜 제한 구조로 구성.

01

모임 생성 — gatherings 테이블

모임 생성 시 is_public 플래그로 공개/비공개 분기. 비공개 모임은 UUID 기반 invite_code를 자동 생성. 생성 시점에 MOIM_PLAN_LIMITS를 확인해 플랜 한도를 초과하면 생성 차단.

gatherings.is_public + invite_code
02

딥링크 초대 패턴

초대 링크는 ?moim={id 또는 invite_code} 쿼리스트링으로 전달. 앱 진입 시 URL을 파싱해 공개 모임은 id, 비공개 모임은 invite_code로 구분하여 참여 처리. 카카오톡 공유 + 클립보드 복사 지원.

Deeplink: ?moim={id | invite_code}
03

모임 채팅 — Supabase Realtime

모임에 참여한 멤버(gathering_applications)는 gathering_chats 테이블을 Realtime으로 구독. 채널명은 moim-chat-{gatheringId}. 메시지 INSERT 이벤트를 수신해 UI에 즉시 반영. 채팅방 이탈 시 채널 removeChannel 처리.

channel: moim-chat-{gatheringId}
04

플랜 한도 강제 (create-time enforcement)

모임 생성 요청 시 현재 유저의 플랜을 확인하고 MOIM_PLAN_LIMITS 객체와 대조. 한도 초과 시 업그레이드 유도 모달을 표시하고 INSERT를 차단. 서버가 없으므로 RLS 정책과 클라이언트 양쪽에서 이중 검증.

MOIM_PLAN_LIMITS enforcement

Technical Highlights
기술적 도전과 해결
01

프레임워크 없이 단일 HTML 파일로 전체 앱 구현

React/Vue 없이 순수 Vanilla JS로 지도·스와이프·채팅·마이페이지·바로모임 등 전체 기능을 바로알바.html 단일 파일(~18,000 라인)에 구현. 배포가 간단하고 CDN 캐싱 효율이 높음. 모든 패널은 position:fixed + transform으로 SPA 수준의 전환 구현.

Single File Architecture
02

Supabase REST API 직접 DML — 서버 코드 없는 보안 접근

모든 INSERT/UPDATE/DELETE는 Supabase REST API를 클라이언트에서 직접 호출. SQL 실행은 사용자에게 위임하지 않고 DDL만 Supabase 콘솔에서 수행. RLS 정책(workers.kakao_uid = auth.uid())이 서버리스 함수 없이 완전한 접근 제어를 담당.

REST API Direct DML
03

Android WebView 키보드 3중 방어 시스템

Android IME 높이를 ViewCompat.setOnApplyWindowInsetsListener로 측정 → JS _onNativeKbChange 콜백으로 전달 → CSS translateY 조정. 채팅 전송 시 SHOW_FORCED로 키보드 강제 유지 + scrollKbGuard로 스크롤 닫힘 방지 + 1.5초 안전장치 자동 해제.

Triple Keyboard Defense
04

이중 Push 알림 시스템 (VAPID + FCM HTTP v1)

브라우저/PWA는 VAPID 기반 Web Push(Vercel 서버리스), Android는 FCM HTTP v1 네이티브 토큰. FCM 토큰은 페이지 로드 전 수신될 수 있어 latestFCMToken에 보관 후 onPageFinished에서 재전달하는 pending token 패턴. push_subscriptions + fcm_tokens 테이블에 비정규화 저장.

Dual Push Architecture
05

바로모임 — UUID invite_code 기반 비공개 초대

비공개 모임은 생성 시 UUID invite_code를 자동 발급. 딥링크 ?moim={invite_code}로 초대받은 사람만 참여 가능. MOIM_PLAN_LIMITS 객체를 create-time에 검증해 플랜 초과 시 서버 요청 없이 클라이언트에서 선제 차단. RLS가 이중으로 서버측 보장.

바로모임 신규 2026.06.30
06

Service Worker v284 — 유형별 캐시 전략 분기

자산(카카오맵 SDK·Supabase JS·이미지)은 Cache-First, HTML·API는 Network-First, 프로필 사진은 Stale-While-Revalidate. sw.js 버전은 바로알바.html의 SW_VERSION 상수와 항상 동기화 — 불일치 시 강제 업데이트. 오프라인에서도 마지막 공고 목록 캐시 표시.

Tiered Cache Strategy
