기술 스택

바로알바를 구성하는 핵심 기술들입니다.

⚡
Vanilla JS PWA
프레임워크 없는 순수 JS. 약 18,000라인 단일 파일(바로알바.html). Service Worker로 오프라인 지원 및 PWA 설치 가능.
ES6+ PWA Service Worker 단일 파일
🗄️
Supabase
PostgreSQL + RLS + Auth + Realtime + Storage. DML은 REST API 직접 호출. DDL만 콘솔에서 실행. BaaS로 백엔드 서버리스 운영.
PostgreSQL RLS Realtime REST API
🌐
Vercel
CDN + Serverless Functions. api/send-push.js로 FCM Web Push 발송 처리. GitHub push → 자동 배포. 글로벌 CDN 엣지.
CDN Serverless 자동배포
📱
Android WebView
WebView 기반 하이브리드 앱. AndroidBridge JavascriptInterface로 JS ↔ Native 통신. GitHub Actions로 AAB 빌드 자동화.
WebView AndroidBridge GitHub Actions
🔔
푸시 알림 이중화
Firebase FCM (Android 네이티브 푸시) + Web Push VAPID (브라우저/PWA). 이중 채널로 알림 누락 방지. api/send-push.js 경유 발송.
FCM VAPID 이중화
🌍
shared-lang.js
7개국어 i18n 엔진 (한국어/영어/중국어/일본어/베트남어/러시아어/몽골어). applyLang() 함수가 DOM 텍스트를 번역값으로 교체.
i18n 7개국어 applyLang()

GitHub Actions CI/CD
Android AAB 서명 빌드 + Google Play 업로드 자동화. 키스토어 시크릿 GitHub Secrets 관리.
06
AndroidBridge 브릿지
JavascriptInterface로 JS → Native 함수 직접 호출. FCM 토큰 전달, 카메라, 갤러리 접근.

Supabase Realtime 채널
채널명 용도 대상 메시지 타입
app_chat:{appId} 1:1 채팅 업주 ↔ 알바생 Broadcast (메시지 전송)
location:{appId} 실시간 위치 공유 당일 알바 중 Broadcast (위치 좌표)
moim-chat-{gatheringId} 바로모임 단체채팅 승인된 참가자 + 주최자 Broadcast (그룹 메시지)
DML vs DDL 원칙
구분 처리 방법 이유 예시
DML (INSERT/UPDATE/DELETE/SELECT) Supabase REST API 직접 RLS 적용 보장, 클라이언트에서 직접 처리 공고 등록, 지원, 채팅 메시지
DDL (CREATE TABLE/ALTER TABLE) Supabase 콘솔 SQL 에디터 스키마 변경은 관리자 권한 필요 신규 테이블 생성, 컬럼 추가

SERVICE WORKER

Service Worker 캐시 전략

3개 레이어 캐시 구조와 버전 동기화 규칙입니다.

🌐
Layer 1
WebView HTTP 캐시
브라우저 기본 HTTP 캐시. 모든 리소스 대상. clearCache(true)로 우회 가능.
📦
Layer 2
SW CacheStorage
JS, CSS, 이미지 대상. Cache-First 전략. SW 버전 올리면 이전 캐시 자동 삭제.
📄
Layer 3
SW HTML 처리
.html 파일. Network-First (no-store) 전략. 항상 최신 버전 로드.
버전 동기화 규칙
바로알바.html ↔ sw.js 항상 동일 버전
SW_VERSION 상수와 캐시 키 이름이 항상 일치해야 합니다
// 바로알바.html const _APP_V = '311'; ← 앱 버전 상수 navigator.serviceWorker.register('./sw.js?v=311'); ← SW 등록 쿼리 파라미터 // sw.js const CACHE = 'baroalba-v311'; ← 캐시 키 (이전 캐시 자동 삭제) // activate 이벤트에서 이전 캐시 삭제 self.addEventListener('activate', e => { e.waitUntil( caches.keys().then(keys => Promise.all(keys.filter(k => k !== CACHE).map(k => caches.delete(k))) ) ); });

핵심: SW 버전을 올리지 않으면 구 버전 JS (shared-lang.js 포함)가 Cache-First로 계속 사용됩니다. v300에서 baroalba-v300으로 bump하여 nav 라벨 버그 수정분이 실제 적용되었습니다.

shared-lang.js applyLang() 버그 분석
🔍 왜 캐시가 아니었나 shared-lang.js
7시간 추적 끝에 발견한 JS 코드 버그 — 755-756번 줄

바로알바 앱은 6~7개 언어 번역을 shared-lang.js에서 관리합니다. 페이지 로드 시 applyLang()이 실행되어 .nav-label 요소들의 textContent를 번역값으로 덮어씁니다.

// shared-lang.js 755-756번 줄 (버그) const navKeys = ['nav_map','nav_swipe','nav_applications','nav_chats','nav_profile']; navLabels.forEach((el, i) => { if (navKeys[i]) el.textContent = t(navKeys[i]); }); // 결과: HTML이 아무리 바뀌어도 JS가 덮어씀 // nav[0] "홈" → '지도' 출력 (nav_map 값) // nav[1] "지도" → '스와이프' 출력 (nav_swipe 값) // 수정 — nav_home 신규 추가, navKeys 재정렬 const navKeys = ['nav_home','nav_map','nav_applications','nav_chats','nav_profile']; // 7개 언어 TRANSLATIONS에 nav_home 추가: ko: nav_home:'홈' en: nav_home:'Home' zh: nav_home:'首页' ja: nav_home:'ホーム' vi: nav_home:'Trang chủ' mn: nav_home:'Нүүр' ru: nav_home:'Главная'
BAROMOIM

바로모임 아키텍처

홈탭에서 진입하는 소셜 모임 서비스의 기술 구조입니다.

1
모임 개설
카테고리, 인원, 공개/비공개 설정. gatherings 테이블 INSERT. 비공개 시 invite_token 생성.
2
참가 신청
공개: 목록에서 바로 신청. 비공개: 딥링크 초대 링크 통해서만 진입. gathering_applications INSERT.
3
주최자 승인
주최자 대시보드에서 pending → approved/rejected. 승인 시 FCM 알림 발송.
4
단체채팅
승인된 참가자 + 주최자만 입장. Supabase Realtime moim-chat-{gatheringId} 채널 Broadcast.
