Critical · New Surface
🌐 “/”가 로그인 화면이었다 — 진짜 서비스 소개 랜딩으로 전환
검색엔진이 보는 첫 화면에 서비스 설명이 한 글자도 없던 상태를 발견하고, 랜딩 신설부터 8개 언어·공고별 URL까지 SEO 기반을 한 구간에 완성.
ROOT CAUSE
공개 랜딩페이지 신설 + JSON-LD 4종 + robots.txt/sitemap.xml
vercel.json이 /를 login.html로 리라이트하고 있었음. index.html을 실제 랜딩으로 채우고 그 리라이트를 제거. 기존 진입 경로(쿼리스트링·저장된 세션)는 그대로 앱으로 보존해 기존 이용자에게 영향 없음.
CTA 막힘
랜딩이 내건 약속이 실제로는 로그인 벽에 막혀 있었음
CTA가 전부 앱으로 가는데, 부팅 분기가 세션/게스트 플래그/딥링크 셋 다 없으면 로그인 화면으로 튕겼음. "가입 없이 둘러볼 수 있습니다"가 거짓이 되고 있던 것을 게스트 플래그로 수정.
NEW
공고별 URL(/job/:id) 서버렌더링 + 사이트맵 자동생성
크롤러가 실행 못 하는 클라이언트 앱 대신 서버가 완성된 HTML을 내려줌. JobPosting 스키마는 필수값이 갖춰진 공고만 출력, 마감 공고는 noindex. Vercel Hobby 12개 함수 상한을 두 번째로 만나 이메일 API 2개를 api/email.js 하나로 합쳐 슬롯을 확보.
BUG
공고 등록 화면 두 경로가 주소를 지우거나 안 채우고 있었음
공고 채움률이 낮은 원인을 "입력을 강제하자"로 바로 갈 뻔했으나, 저장 경로를 따라가 보니 공고 복사가 주소를 빈 문자열로 덮어쓰고 있었고 지도 검색 폴백은 화면 표시만 하고 실제 저장 필드엔 안 넣고 있었음. 두 경로 수정 + 설명 15자·주소 필수 검증 추가.
i18n Complete
🗣️ 8개 언어가 사실상 도달 불가능했다 — 자동감지 복구 + 토스트 158개 전수번역
여러 세션에 걸쳐 8개 언어로 번역해뒀지만, 정작 그 언어 사용자에게 자동으로는 닿지 않고 있던 구조적 공백을 발견.
ROOT CAUSE
저장된 언어 선택이 없으면 무조건 한국어 — 브라우저 언어 감지 코드 자체가 없었음
네팔 노동자가 앱을 처음 열면 한국어가 뜨고, 자기 언어를 보려면 읽지도 못하는 화면에서 언어 버튼을 먼저 찾아야 했음. 저장값이 없을 때만 navigator.language를 따르도록 수정(사용자 선택은 항상 우선, 감지값 자체는 저장 안 함).
TRAP
네팔어 코드 불일치(ISO ne ↔ 앱 내부 np) — 두 번 밟은 함정
브라우저는 표준코드 ne로 보내는데 앱 내부 키는 국가코드 np. 매핑 없으면 네팔 휴대폰이 조용히 한국어로 떨어짐. 랜딩 JSON-LD inLanguage에도 동일 적용.
FEAT
랜딩 페이지 8개 언어 지원 + 페이지 내 언어 선택기
본문 83개 키 번역. 초기 언어는 ?lang= > 저장된 선택 > 브라우저 언어 순. 저장 키를 앱과 동일한 baroalba_lang으로 통일해 랜딩에서 고른 언어가 앱까지 이어짐. 언어 전환 시 FAQ 구조화 데이터도 함께 재작성.
BUG
홈 화면 공고 카드 렌더링 + 토스트 알림 전수 번역
날짜슬라이더·지역필터·마커 카테고리 23종·만원 축약 표기(한국어 "1.2만원" 유지, 나머지 7개 언어 "12k" 통일) 등 신규 키 약 45개 적용(i18n 4차). 이어서 하드코딩된 showToast('한국어') 155건(고유 127개) + 문자열 연결·템플릿 리터럴 형태로 숨어있던 것까지 4개 배치로 전수 번역, 총 158개 신규 키 × 8개국어(i18n 5차).
Root-Cause Fixes
🔔 업주 지원자 알림이 항상 0건이던 버그 — 원인이 3겹이었다
대표님 실기기 제보 3건에서 시작해 "전에 얘기했는데 절반만 반영된" 유형의 버그들을 연속으로 근본 수정.
3겹 원인
업주 지원자 알림 0건 — 스키마 드리프트 사본 누락 + 알바생 전용 종 + 뱃지 부재
① applications.updated_at(라이브 DB에 없는 컬럼)을 조회해 쿼리 전체가 400 → 조용히 빈 배열. 이미 2026-07-19에 알바생 쪽은 고쳤던 버그의 업주 쪽 사본을 놓쳤던 것 — 같은 로직이 파일 안에 두 벌 존재한다는 전제 없이 한 벌만 고쳤기 때문. ② 홈 화면 종은 알바생이 지원한 건만 보고 업주 알림은 별도 종에만 있었음. ③ 그 홈 종엔 뱃지 요소 자체가 없었음. 셋을 함께 수정 + #home-noti-badge 신설.
교훈
schema.sql엔 있지만 실제 DB엔 없었다 — 문서가 아니라 라이브 REST로 확인할 것
스키마 문서 파일과 실제 운영 DB가 어긋나 있던 사례. 컬럼 존재 여부 판단은 항상 살아있는 DB 쿼리 기준으로.
BUG
공고 카드 UI가 6곳 중 2곳만 통일 적용돼 있었음
이전 통일 작업이 검색결과 렌더러 2곳만 처리하고 급구피드·홈공고카드·AI추천·홈검색결과 4곳은 그대로였음 — 같은 검색인데 결과 카드가 진입 경로에 따라 다른 앱처럼 보이던 상태. 나머지 4곳도 동일 위계로 통일.
BUG
로그인 화면이 상태표시줄을 침범 — 독립 HTML은 전역 안전영역 처리가 자동으로 안 따라온다
login.html은 앱 CSS/JS를 안 써서 안전영역 체계(--sat/--sab)와 viewport-fit=cover가 아예 없었음. 앱에서 이미 풀어놓은 로직을 그대로 이식.
BUG
12일 지난 바로스팟이 “모집 중”으로 홈에 계속 노출
형제 기능인 바로모임엔 날짜 필터가 있는데 바로만남 쪽 두 화면에만 없었음. status만 믿으면 안 됨 — 자동마감 함수는 본인이 만든 것만 닫고, 바로스팟은 자동마감 로직 자체가 없었음.
BUG
공고 주소가 “업체명+도로명주소”로 붙어서 저장 — 지역 표시가 전 화면에서 깨짐
<input>은 대입값의 개행을 조용히 지운다(<textarea>는 유지). 렌더러가 개행 기준으로 지역을 뽑고 있어 전 화면에서 깨져 있었음. hidden 필드 분리 + 기존 데이터 복구 함수로 해결.
Field Feedback & Infra

BUG
“모임 둘러보기”·“바로만남 살펴보기” CTA가 실제로는 그 화면을 안 열고 있었음
앱 홈(게스트)으로만 떨어지고 패널 자체를 여는 딥링크 값이 없었음. ?panel=moim|mannam 신설. 링크가 200을 주는 것과 사용자가 실제 그 화면을 볼 수 있는 것은 다르다는 교훈의 재확인.
UX
랜딩 로고·브랜드 표기·언어 선택 UI 정리
랜딩만 자체 제작 SVG 로고를 쓰던 것을 앱과 동일 마크로 통일, "바로알바"가 flex 컨테이너 익명 아이템 규칙 때문에 "바로 알바"로 벌어지던 것 수정, 언어 셀렉트가 가장 긴 옵션 기준으로 폭이 잡히던 문제를 유령 span sizer로 해결.
INFRA
공고 자동마감을 서버 크론으로 이식
기존엔 업주가 로그인해야만, 그 업주 소유 공고에 한해서만 자동마감이 돌고 있었음. 기존 api/surge-check.js 크론 핸들러 안에 편입(함수 상한 유지, 새 파일 없음).
SECURITY
⚠️ /api/surge-check에 사실상 인증이 없다
CRON_SECRET 환경변수 자체가 없어 시크릿 비교가 undefined !== undefined로 항상 통과됨. 시크릿 헤더 없이 아무나 호출해도 200이 뜨고 실제로 임금 서지·공고 마감을 트리거함. 값 설정 + cron-job.org 헤더 동기화가 필요(외부 서비스 계정 작업).

color-scheme 메타가 없어 Android WebView가 페이지를 다크모드 미지원으로 보고 색을 알고리즘으로 반전시키고 있었음. 3개 파일에 light 단독 선언 추가.
